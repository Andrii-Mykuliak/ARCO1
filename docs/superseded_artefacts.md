# Superseded artefacts

Files listed here are retained for the record. They are **not** current evidence,
are **not** cited by the manuscript or the supplements, and must not be reused as
if they described the frozen canonical state.

Nothing in this file is read by any pipeline, guard or builder. It exists so that
an artefact which looks publication-ready cannot be picked up by mistake.

---

## `results/f1_highlights/tables/masking_ablation_mcs35.csv`

**Status: superseded / non-canonical. Do not cite.**

A controlled entity-masking ablation (masked vs unmasked, everything else held
fixed), generated by `scripts/masking_ablation_mcs35.py`.

**Why it is not current.** Its own baseline arm does not reproduce the canonical
partition. The generator and the companion provenance record
(`outputs/ablation_labels/masking_mcs35_labels_provenance.json`) both state the
canonical configuration — all-MiniLM-L6-v2, UMAP(n_neighbors=15, min_dist=0.0,
n_components=5, cosine, seed 42), HDBSCAN(min_cluster_size=35, euclidean, EOM),
7,647 sentences — yet the run returned:

| arm | clusters | noise |
|---|---|---|
| "masked (canonical)" in this file | 32 | 31.5% |
| **frozen canonical partition** | **34** | **33.516%** |

A baseline that returns 32 clusters is not the 34-category structure every
reported result is computed on, so the masked/unmasked contrast in this file is
not a contrast against the canonical taxonomy. The discrepancy is the same class
of environment-dependent non-reproduction already documented for the
resampling-stability dimension in the manuscript.

It was committed in the release-kit commit whose message describes the retired
"four-axis validation protocol", a framing the manuscript no longer uses.

**Consumers.** None that are publication-facing. No manuscript builder, no
supplement builder, no figure and no table reads it. It is referenced only by its
own generator, by `outputs/` bookkeeping tables, and by
`results/_pre_cleanup_hashes.json`, which is a historical hash record that no
code reads.

**Why it was not moved or deleted.** `results/_pre_cleanup_hashes.json` binds the
path `results/f1_highlights/tables/masking_ablation_mcs35.csv` to sha256
`d43b9d3d…`, and that hash still matches the file byte for byte. Moving or
renaming the file would leave that integrity record pointing at nothing, so the
file is left in place and marked here instead.

**What the manuscript actually claims about masking.** Section 3.4 states only
that "the influence of masking on lexical characterisation is examined in
Section 5.1", which is the placeholder-retained versus placeholder-stripped
comparison of enriched vocabulary reported there. The manuscript makes no claim
about the effect of masking on the recovered structure, and no structural masking
ablation is cited anywhere.
